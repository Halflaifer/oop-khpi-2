# Лабораторна робота №5: Успадкування в Java

## 1. Опис ієрархії (Варіант №12)
Для виконання роботи побудовано чотирирівневу ієрархію класів за принципом «є різновидом» (is-a), що описує ресторанне меню:

* **MenuItem (Елемент меню)** — Базовий клас, що містить назву (name) та ціну (price).
* **Beverage (Напій)** — Спеціалізація елемента меню, що додає поле об'єму в мілілітрах (volumeMl).
* **Coffee (Кава)** — Спеціалізація напою, що містить інформацію про ступінь обсмаження зерен (roastLevel).
* **SpecialtyCoffee (Спеціальна кава)** — Кінцевий клас із модифікатором `final`, що додає регіон походження зерен (originRegion).

## 2. Реалізація ключових концепцій
* **Конструктори та `super()`**: Кожен підклас ініціалізує власний стан та передає параметри базовим конструкторам через `super(...)` для коректного створення об'єкта.
* **Перевизначення (@Override)**: Метод `description()` перевизначений на кожному рівні. Він викликає версію методу батьківського класу та доповнює її новими даними про поточний рівень ієрархії.
* **Модифікатор `final`**: Використаний для класу `SpecialtyCoffee`, щоб позначити завершеність ієрархії та заборонити подальше успадкування від цього типу.

## 3. Результати JOL-дослідження
Аналіз структури об'єкта `SpecialtyCoffee` в пам'яті за допомогою Java Object Layout (JOL) показав наступне:

1.  **Цілісність об'єкта**: Екземпляр підкласу є одним неперервним об'єктом у пам'яті, а не сукупністю вкладених об'єктів.
2.  **Розміщення полів**: Поля всіх рівнів ієрархії розміщуються послідовно всередині одного екземпляра. У таблиці виводу видно поля батьківського класу (MenuItem), за якими слідують поля Beverage, Coffee та SpecialtyCoffee.
3.  **Розмір об'єкта**: З кожним рівнем успадкування фізичний розмір об'єкта збільшується за рахунок накопичення стану (полів) усіх батьківських класів. У нашому випадку загальний розмір (Instance size) склав 40 байт.

## 4. Аналіз моделі з ЛР №2
У попередній роботі (автобусний парк) було використано асоціацію (маршрут посилався на автобус). Проте, предметна область дозволяє впровадити успадкування: наприклад, створити базовий тип `Vehicle` (Транспортний засіб) для спільних атрибутів автобусів та вантажівок (марка, номер, рік випуску). Це дозволило б узагальнити логіку обробки транспортних засобів та уникнути дублювання коду.
