# Звіт з лабораторної роботи №12

**Дисципліна:** Об'єктно-орієнтоване програмування  
**Тема:** Stream API в Java  
**Варіант:** №12 — ІоТ-моніторинг  

---

## 1. Мета роботи
Метою роботи є опанування технології Java Stream API для декларативної обробки даних. Робота спрямована на вивчення методів фільтрації, трансформації, сортування та агрегування колекцій об'єктів без використання явних циклів.

---

## 2. Опис предметної моделі
Предметна область «ІоТ-моніторинг» реалізована за допомогою таких класів:
* **Sensor**: модель датчика (ідентифікатор та тип: температура, вологість тощо).
* **Measurement**: модель одиничного вимірювання, що містить посилання на датчик, числовий показник, часову мітку та рівень тривоги.
* **AlertType**: перелік (enum) рівнів критичності показників (INFO, WARNING, CRITICAL).
* **MonitoringService**: сервіс, що акумулює дані та виконує їх аналітичну обробку за допомогою потоків (streams).

---

## 3. Використання Stream API
У програмі реалізовано обробку даних за допомогою таких операцій Stream API:

1.  **filter**: відбір вимірювань, що мають статус `CRITICAL`.
2.  **map**: отримання списку числових значень (double) з об'єктів вимірювань.
3.  **sorted**: сортування результатів за значенням показника.
4.  **average**: обчислення середнього значення всіх отриманих даних.
5.  **max**: знаходження вимірювання з максимальним числовим показником.
6.  **collect(groupingBy)**: групування всіх вимірювань за рівнем тривоги (AlertType).

---

## 4. Опис реалізації
* **Декларативний підхід**: Замість використання ітераторів та циклів `for/while`, вся логіка фільтрації та пошуку реалізована через конвеєри методів Stream API.
* **Безпека (Optional)**: Методи агрегації (max, average) повертають об'єкти `Optional` та `OptionalDouble`, що дозволяє коректно обробляти ситуації з порожніми вхідними даними.
* **Лямбда-вирази**: Для передачі логіки в методи потоків використані лямбда-вирази та посилання на методи (`Measurement::getValue`).
* **Незмінність**: Результати обробки збираються у нові списки або мапи, не змінюючи вихідну колекцію даних.

---

## 5. Тестування
Коректність роботи Stream-запитів перевірена за допомогою Unit-тестів:
* Тест `testGetCriticalAlerts`: перевірка точності фільтрації за категорією.
* Тест `testGetAverageValue`: порівняння результату Stream-агрегації з очікуваним математичним значенням.
* Тест `testGroupByAlertType`: перевірка правильності розподілу об'єктів за ключами мапи.
* Тест на порожніх даних: перевірка відсутності винятків при роботі з порожніми потоками.

---

## Висновок
Під час виконання роботи було вивчено інструментарій Stream API, що дозволяє писати більш лаконічний та читабельний код для обробки великих наборів даних. Використання функціонального підходу в Java спрощує паралельну обробку та зменшує кількість помилок, пов'язаних із керуванням станом ітераторів.
