# Звіт з лабораторної роботи №14

**Дисципліна:** Об'єктно-орієнтоване програмування  
**Тема:** Базова багатопотоковість у Java  
**Варіант:** №12 — ІоТ-моніторинг  

---

## 1. Мета роботи
Метою роботи є набуття практичних навичок проектування та розробки багатопотокових застосунків на мові Java. Завдання спрямоване на вивчення життєвого циклу потоків, опанування інтерфейсу `Runnable`, реалізацію взаємодії потоків через розділювану пам'ять (патерн "Виробник-Споживач") та забезпечення синхронізації доступу до ресурсів за допомогою ключового слова `synchronized` і методів `wait()` та `notifyAll()`.

---

## 2. Опис предметної моделі
Для симуляції паралельної роботи системи «ІоТ-моніторинг» було створено такі класи:
* **SensorData**: Об'єкт предметної галузі, що представляє одне вимірювання (ідентифікатор датчика, згенероване числове значення температури та часова мітка).
* **DataBuffer**: Потокобезпечний проміжний буфер (черга з обмеженою місткістю), який координує паралельний доступ: не дозволяє датчикам додавати дані, якщо буфер заповнений, і не дозволяє аналізатору зчитувати дані, якщо буфер порожній.
* **SensorSimulator**: Клас, який реалізує інтерфейс `Runnable`. Він описує поведінку потоку-виробника (продюсера), який імітує роботу реального фізичного датчика й періодично генерує вимірювання.

---

## 3. Механізми багатопотоковості та синхронізації
У програмі реалізовано такі фундаментальні концепції конкурентного програмування:

1. **Інтерфейс Runnable**: Поведінку потоків-датчиків винесено в окремий клас шляхом реалізації `Runnable`, що є більш гнучким підходом, ніж пряме наслідування від `Thread`.
2. **Монітор об'єкта та Кcritical Section**: Методи `put()` та `take()` у класі `DataBuffer` оголошені як `synchronized`. Це гарантує, що лише один потік у конкретний момент часу може модифікувати внутрішню чергу, запобігаючи стану гонитви (race condition).
3. **Міжпотокова взаємодія (wait/notify)**: Замість неефективного "активного очікування" (busy waiting) використано блоки `while` із викликом `wait()`. Коли умовний стан змінюється, потік викликає `notifyAll()`, щоб пробудити інші потоки, які чекають у черзі монітора.
4. **Координація через Thread.join()**: Головний потік програми (`Main`) використовує метод `join()`, щоб заблокувати своє виконання й дочекатися, поки всі фонові потоки-датчики та потік-аналізатор повністю завершать свою роботу.

---

## 4. Опис логіки роботи конвеєра
1. У системі створюється один спільний об'єкт `DataBuffer` з обмеженою ємністю (наприклад, 3 елементи).
2. Ініціалізуються та запускаються 3 незалежні потоки-датчики (`TEMP-01`, `TEMP-02`, `TEMP-03`). Кожен із них паралельно в асинхронному режимі генерує по 5 вимірювань температури з випадковим інтервалом часу.
3. Одночасно запускається окремий потік-аналізатор (споживач), який у циклі послідовно вилучає вимірювання з буфера, обробляє їх і виводить аналітичну інформацію на консоль.
4. Синхронізація методів всередині буфера автоматично регулює швидкість роботи: якщо аналізатор не встигає обробляти дані, датчики тимчасово засинають, звільняючи процесорний час.

---

## 5. Тестування потокобезпечності
Для перевірки логіки роботи буфера було написано модульний JUnit-тест:
* `testBufferPutAndTake`: Перевіряє роботу методів `put()` та `take()` в ізольованому середовищі. Тест підтверджує, що дані додаються у правильній послідовності (FIFO), лічильник елементів змінюється коректно, а вилучений об'єкт повністю відповідає початково записаному, що доводить надійність блокувань монітора.

---

## Висновок
Під час виконання лабораторної роботи було успішно освоєно базові інструменти Java для створення багатопотокових застосунків. Реалізація класичного шаблону "Виробник-Споживач" на практиці продемонструвала переваги асинхронної обробки даних, де генерація показників датчиків та їх аналіз відбуваються у паралельних потоках. Використання методів `wait()`/`notifyAll()` дозволило побудувати енергоефективну систему координації, що виключає зайве навантаження на CPU. Код програми повністю сумісний із Java 8 завдяки використанню базових моніторів синхронізації.
