# Звіт з лабораторної роботи №10

**Дисципліна:** Об'єктно-орієнтоване програмування  
**Тема:** Узагальнені контейнери та ітератори в Java  
**Варіант:** №12 — Система документообігу  

---

## 1. Мета роботи
Набуття практичних навичок проєктування власних узагальнених контейнерів на основі масивів, реалізація логіки динамічного керування пам'яттю та опанування механізму ітерації за допомогою паттерна Iterator.

---

## 2. Опис предметної моделі
Для демонстрації роботи контейнера використано модель документа (`Document`). Клас інкапсулює базові атрибути (назва документа) та реалізує методи `equals()` і `hashCode()`, що є необхідним для коректного пошуку, порівняння та видалення об'єктів усередині колекції.

---

## 3. Реалізація узагальненого контейнера
В межах роботи було розроблено клас `DocumentContainer<T>`, який виконує роль динамічного масиву:
* **Внутрішня структура:** Дані зберігаються у приватному масиві типу `Object[]`.
* **Динамічне розширення:** Реалізовано метод `grow()`, який автоматично збільшує ємність масиву вдвічі, коли він заповнюється, що дозволяє контейнеру масштабуватися.
* **Основні операції:** Реалізовано методи додавання елементів (`add`), отримання за індексом (`get`), визначення поточного розміру (`size`) та повного очищення сховища (`clear`).

---

## 4. Реалізація паттерна Iterator
Контейнер реалізує інтерфейс `Iterable<T>`, що дозволяє використовувати його у стандартних циклах `for-each`. Логіка обходу елементів винесена у внутрішній анонімний клас, який реалізує інтерфейс `Iterator<T>`:
* **Метод `hasNext()`:** Перевіряє наявність наступного елемента у масиві.
* **Метод `next()`:** Повертає поточний об'єкт та переміщує курсор на наступну позицію.
Такий підхід забезпечує інкапсуляцію: користувач контейнера отримує доступ до елементів, не знаючи про внутрішню реалізацію сховища.

---

## 5. Обробка виняткових ситуацій
Для підвищення надійності було створено власний клас винятку `DocumentContainerException`. Він використовується для обробки специфічних помилок контейнера, таких як:
* Спроба звернення за некоректним індексом.
* Помилки під час ітерації по порожній колекції.
Використання власного винятку дозволяє відокремити логічні помилки бізнес-логіки контейнера від системних помилок Java.

---

## 6. UML-діаграма
Діаграма відображає архітектурні зв'язки між інтерфейсами Java (`Iterable`, `Iterator`) та створеним класом `DocumentContainer`. Також на діаграмі показано відношення агрегації між контейнером та об'єктами моделі `Document`.

---

## Висновок
Під час виконання роботи було реалізовано узагальнений контейнер, який є спрощеним аналогом стандартних колекцій Java. Це дозволило глибше зрозуміти механізми роботи з динамічними структурами даних, принципи "стирання типів" (Type Erasure) та переваги використання паттерна Ітератор для доступу до даних.
