# Звіт з лабораторної роботи №8

**Дисципліна:** Об'єктно-орієнтоване програмування
**Тема:** Файлове введення-виведення, серіалізація та винятки в Java
**Варіант:** №12 — Система документообігу

---

## 1. Мета роботи
Сформувати практичні навички роботи з файловим введенням/виведенням у Java, опанувати текстове та бінарне подання даних, навчитися застосовувати механізми серіалізації об'єктів та обробку виняткових ситуацій.

---

## 2. Опис предметної моделі
Модель системи документообігу побудована з чітким розділенням на логічні шари для забезпечення чистоти архітектури:

* **Document** (пакет `model`) — абстрактний базовий клас, що описує спільні атрибути документів (назва, автор) та реалізує інтерфейс `Serializable` для можливості збереження стану.
* **ContractDraft** — конкретний клас, що розширює базову модель та додає специфічні поля, як-от бюджет контракту.
* **DocumentRegistry** (пакет `service`) — клас-контейнер, що виконує роль реєстру та керує колекцією об'єктів у пам'яті програми.
* **DocumentFileManager** (пакет `persistence`) — сервісний клас, який інкапсулює логіку взаємодії з файловою системою.

---

## 3. Методи збереження даних
У роботі реалізовано два взаємодоповнюючі підходи до збереження даних:

1.  **Текстовий формат:** Дані записуються у людиночитаному вигляді з використанням розділювача `;`. Кожен об'єкт представлений окремим рядком, що дозволяє легко переглядати та редагувати файл за допомогою звичайних текстових редакторів.
2.  **Бінарна серіалізація:** Використовується стандартний механізм Java для створення бінарного "знімка" всього реєстру документів. Це забезпечує максимальну швидкість відновлення об'єктів зі збереженням усіх внутрішніх зв'язків.

---

## 4. Обробка виняткових ситуацій
Програма розроблена з урахуванням принципів надійності та стійкості до помилок:

* **Управління ресурсами:** Застосовано конструкцію `try-with-resources`, яка гарантує коректне закриття файлових потоків навіть у разі виникнення критичних помилок.
* **Користувацькі винятки:** Створено спеціалізований клас `InvalidDocumentDataException`. Він дозволяє відокремити технічні помилки доступу до файлів від логічних помилок у структурі самих документів.
* **Валідація:** Реалізовано перевірку вхідних параметрів на етапі створення об'єктів та зчитування їх з файлу, що запобігає появі некоректних даних у системі.

---

## 5. UML-діаграма
Діаграма відображає структуру пакетів та взаємозв'язки між ними. Чітко виділено шари моделі, сервісів та збереження, що відповідає принципу єдиної відповідальності (Single Responsibility Principle).

---

## Висновок
Під час виконання роботи було реалізовано повноцінну систему збереження даних. Використання текстового формату забезпечує прозорість даних, тоді як серіалізація дозволяє ефективно зберігати складні об'єктні графи. Належна обробка винятків забезпечує стабільну роботу програми у разі виникнення непередбачуваних ситуацій із зовнішніми файлами.
