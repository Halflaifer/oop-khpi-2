# Звіт з лабораторної роботи №11

**Дисципліна:** Об'єктно-орієнтоване програмування  
**Тема:** Collections Framework в Java  
**Варіант:** №12 — Подорожі та маршрути  

---

## 1. Мета роботи
Метою роботи є формування практичних навичок використання стандартних колекцій Java: вибір відповідного типу колекції для конкретного завдання, організація зберігання наборів об'єктів, виконання базових операцій над ними та обґрунтування впливу вибору структури даних на архітектуру програми.

---

## 2. Опис предметної моделі
Для реалізації завдання обрано предметну галузь «Подорожі та маршрути». Модель складається з таких основних класів:
* **TripStop**: сутність, що описує зупинку маршруту (унікальний ID, назва міста, назва станції чи вокзалу).
* **Ticket**: сутність, що описує квиток (номер квитка, ім'я пасажира, ID цільової зупинки).
* **RouteManager**: сервісний клас-реєстр, який інкапсулює стандартні колекції для керування даними про маршрут.

---

## 3. Обґрунтування вибору колекцій
У роботі використано три різні типи колекцій для виконання специфічних завдань у межах сервісу:

| Інтерфейс | Реалізація | Роль у моделі | Обґрунтування |
| :--- | :--- | :--- | :--- |
| **List<E>** | `ArrayList` | Послідовність зупинок | Для маршруту важливо зберігати строгий порядок додавання пунктів призначення. |
| **Map<K, V>** | `HashMap` | Швидкий пошук за ID | Забезпечує миттєвий доступ до об'єкта зупинки за її унікальним кодом (O(1)). |
| **Set<E>** | `HashSet` | Перелік унікальних міст | Гарантує зберігання списку міст без дублікатів, автоматично відсікаючи повтори. |

---

## 4. Опис реалізації
* **Параметризація (Generics):** Усі колекції використовують сувору типізацію, що виключає використання "сирих" типів та забезпечує перевірку помилок на етапі компіляції.
* **Інкапсуляція:** Колекції оголошені як приватні поля (`private final`). Доступ до них ззовні надається лише через методи, що повертають незмінні представлення даних за допомогою методів `Collections.unmodifiable...`.
* **Узгодженість:** Метод додавання зупинки одночасно оновлює всі три внутрішні колекції (список, мапу та множину). Перед додаванням перевіряється унікальність ключа в `Map`.
* **Контракти:** Класи моделі реалізують методи `equals()` та `hashCode()` на основі унікального ідентифікатора, що є обов'язковим для коректної роботи в хеш-колекціях.

---

## 5. Тестування
Розроблено набір модульних тестів (JUnit 5), що підтверджують коректність роботи сервісу:
* Перевірка збереження порядку зупинок у списку (відповідність індексів).
* Перевірка правильності та швидкості пошуку об'єкта за ключем у мапі.
* Перевірка унікальності елементів у множині міст (усунення дублікатів).
* Перевірка виникнення винятку при спробі додати зупинку з ідентифікатором, що вже існує.

---

## Висновок
Під час виконання роботи було опановано використання Java Collections Framework. Використання стандартних бібліотечних інструментів дозволило відмовитися від ручного керування масивами, забезпечило високу надійність коду, типобезпеку та оптимальну продуктивність операцій пошуку й обробки даних.
