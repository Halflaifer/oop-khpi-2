# Звіт з лабораторної роботи №7

**Дисципліна:** Об'єктно-орієнтоване програмування
**Тема:** Інтерфейси та множинна реалізація інтерфейсів у Java
**Варіант:** №12 — Система документообігу

---

## 1. Мета роботи
Сформувати практичні навички проєктування моделей Java з використанням інтерфейсів як контрактів, реалізації кількох інтерфейсів в одному класі та використання інтерфейсів як типів даних.

---

## 2. Опис предметної області та контрактів
Для системи документообігу було визначено два поведінкові контракти (ролі), які можуть виконувати різні документи:

* **Approvable** (Затверджуваний) — контракт для об'єктів, що потребують офіційного схвалення (метод `approve()`).
* **Signable** (Підписуваний) — контракт для об'єктів, які мають бути підписані сторонами (метод `sign()`).

---

## 3. Реалізація моделі
У проєкті реалізовано три конкретні класи:

1.  **ContractDraft** (Чернетка контракту) — реалізує **обидва** інтерфейси (`Approvable` та `Signable`). Це дозволяє моделювати життєвий цикл документа: спочатку затвердження, потім підписання.
2.  **PurchaseRequest** (Запит на закупівлю) — реалізує інтерфейс `Approvable`.
3.  **LeaveApplication** (Заява на відпустку) — реалізує інтерфейс `Approvable`.

---

## 4. Обґрунтування використання інтерфейсів
Використання інтерфейсів у цьому випадку є доречнішим за успадкування з наступних причин:
* **Незалежність ролей:** Затвердження та підписання — це незалежні можливості. Не всі документи, що затверджуються, мають бути підписані.
* **Гнучкість типів:** Інтерфейси дозволяють об'єднувати класи, які не мають спільного стану або базового класу, за їхньою поведінкою.
* **Множинна реалізація:** Java не підтримує множинне успадкування класів, тому інтерфейси — єдиний спосіб надати об'єкту кілька незалежних ролей.

---

## 5. Демонстрація поліморфізму
У клієнтському коді (`Main.java`) продемонстровано роботу через типи інтерфейсів:
* Обробка масиву `Approvable[]`, що містить об'єкти різних класів.
* Використання одного об'єкта `ContractDraft` через два різні інтерфейсні подання без явного приведення типів.

---

## 6. UML-діаграма
Діаграма відображає інтерфейси, класи та зв'язки реалізації (пунктирні стрілки). Клас `ContractDraft` візуально пов'язаний з двома контрактами, що наочно демонструє множинну реалізацію.

---

## Висновок
Під час виконання роботи було опановано механізм інтерфейсів у Java. Модель побудована навколо контрактів, що описують, що об'єкт може робити, а не чим він є, що відповідає принципам інтерфейсно-орієнтованого проєктування.
