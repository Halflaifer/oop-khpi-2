# Звіт з лабораторної роботи №9

**Дисципліна:** Об'єктно-орієнтоване програмування  
**Тема:** Узагальнення (Generics) в Java  
**Варіант:** №12 — Система документообігу (відповідає варіанту №11 за переліком ЛР9)  

---

## 1. Мета роботи
Набуття практичних навичок використання узагальнених типів у Java, проєктування типобезпечних узагальнених класів і методів, а також застосування базових обмежень параметрів типів для побудови змістовних компонентів предметної області.

---

## 2. Опис предметної моделі
У межах роботи було реалізовано модель системи документообігу, де основна увага приділена повторному використанню абстракцій без втрати інформації про типи. Основні класи моделі:

* **Document** — сутність документа, що реалізує інтерфейс `Comparable` для можливості порівняння документів за назвою.
* **Employee** — клас, що представляє співробітника (погоджувача).
* **Approval** — сутність, що містить деталі рішення про погодження (статус, коментар, дата).
* **ApprovalEntry<TDoc, TMeta>** — узагальнений клас, який слугує універсальним записом для зв'язування документа з метаданими погодження.

---

## 3. Реалізація Generic-компонентів
Проєкт містить наступні реалізації узагальнень:

1.  **Узагальнений клас (`ApprovalEntry`):** Використовує два параметри типу для типобезпечного зв'язування основної сутності з метаданими. Це дозволяє уникнути використання типу `Object` та необхідності явних приведень типів.
2.  **Узагальнений метод (`findMax`):** Реалізований у класі `Main` для пошуку "найбільшого" елемента у списку.
3.  **Обмеження типу (Type Bound):** Параметр типу в методі `findMax` обмежений контрактом `T extends Comparable<T>`, що дозволяє порівнювати об'єкти предметної області.

---

## 4. Обґрунтування використання Generics
Використання узагальнень у цій лабораторній роботі є виправданим, оскільки:
* **Типобезпека:** Помилки виявляються на етапі компіляції, а не під час виконання програми.
* **Повторне використання:** Один узагальнений клас породжує різні параметризовані типи без дублювання структури компонента.
* **Якість API:** Клієнтський код стає зрозумілішим і не містить небезпечних приведень типів.

---

## 5. Демонстрація роботи
У головному класі `Main` продемонстровано використання generic-компонента у різних конкретизаціях:
* `ApprovalEntry<Document, Employee>` — зв'язок документа з відповідальною особою.
* `ApprovalEntry<Document, String>` — зв'язок документа з текстовим статусом.
* `ApprovalEntry<Document, Approval>` — зв'язок документа зі складним об'єктом погодження.

Також перевірено роботу узагальненого методу `findMax` на списках документів та цілих чисел.

---

## 6. UML-діаграма
Діаграма відображає структуру узагальненого класу `ApprovalEntry` з параметрами типів та його місце в загальній архітектурі системи. Поділ на пакети `model` та `demo` демонструє відокремлення узагальненої логіки від демонстраційного коду.

## Висновок
Під час виконання роботи було опановано механізм Generics у Java. Створені узагальнені компоненти дозволили поєднати універсальність архітектури з надійною типобезпекою, що є критично важливим для систем документообігу.
