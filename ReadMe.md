# Лабораторна робота №6: Поліморфізм з абстрактними класами

## 1. Опис варіанта (Варіант №12)
Тема роботи: **Завдання екологічного моніторингу**.
Мета роботи — реалізація ієрархії класів з використанням абстрактного базового типу та демонстрація поліморфної поведінки об'єктів.

## 2. Структура ієрархії
Ієрархія побудована навколо абстрактного поняття моніторингового завдання:

* **MonitoringTask (Абстрактний клас)** — визначає спільний стан для всіх типів моніторингу (локація та час проведення) та встановлює обов'язковий контракт через абстрактний метод `executeTask()`.
* **TemperatureMonitoring (Конкретний клас)** — реалізує перевірку температурного режиму в заданій локації.
* **AirQualityMonitoring (Конкретний клас)** — реалізує аналіз індексу якості повітря (AQI).
* **NoiseMonitoring (Конкретний клас)** — реалізує вимірювання рівня звукового тиску в децибелах.

## 3. Обґрунтування використання абстрактного класу
Клас `MonitoringTask` визначено як абстрактний, оскільки створення його екземплярів не має сенсу. У реальному світі не існує "просто завдання", воно завжди має конкретну специфікацію (температура, шум тощо). Використання абстрактного класу дозволяє:
* Уникнути дублювання коду для збереження локації та часу.
* Гарантувати, що кожен нащадок реалізує метод виконання завдання.

## 4. Демонстрація поліморфізму
У програмі продемонстровано механізм динамічної диспетчеризації. Об'єкти різних типів (температура, повітря, шум) зберігаються в одному масиві базового типу `MonitoringTask[]`. 

При переборі масиву в циклі викликається один і той самий метод `executeTask()`, проте Java автоматично визначає та виконує потрібну реалізацію залежно від фактичного типу об'єкта. Це дозволяє обробляти різні типи моніторингу єдиним уніфікованим способом.

## 5. Додаткове завдання (Транспортна модель)
В контексті попередніх робіт (автобусний парк) принципи цієї лаби можна застосувати через створення абстрактного класу `Vehicle`. Кожен конкретний вид транспорту (Bus, Truck, Taxi) буде реалізовувати свій специфічний метод `calculateEfficiency()` або `performService()`. Це дозволить системі керування парком працювати з будь-яким транспортом через спільний інтерфейс.
