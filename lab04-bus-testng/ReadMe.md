# Лабораторна робота №4
## Модульне тестування за допомогою TestNG

### Мета роботи
Набуття практичних навичок використання фреймворку TestNG для модульного тестування Java-проєктів: застосування анотацій життєвого циклу, групування тестів, параметризації та налаштування запуску через XML-конфігурацію.

### Опис предметної галузі
Предметна область залишається незмінною з попередніх робіт — система керування автобусними рейсами.Основна увага приділяється тестуванню взаємодії об'єктів `Bus`, `Driver` та `Route` .

### Реалізація тестування в TestNG
У цій роботі було реалізовано розширені можливості тестування, які надає TestNG:

* [cite_start]**Анотації життєвого циклу:** Використано `@BeforeMethod` для підготовки фікстури (створення нових об'єктів водія та автобуса) перед кожним тестом.
* **Групування тестів:** Тестові методи розділені на групи за допомогою параметра `groups`:
    * `smoke` — для швидкої перевірки базової функціональності.
    * `negative` — для перевірки обробки некоректних вхідних даних.
    * `boundary` — для перевірки граничних значень параметрів.
* **Параметризація:** Реалізовано метод `@DataProvider`, який постачає набори даних для тестів, що дозволяє уникнути дублювання коду та перевірити методи з різними аргументами.
* [cite_start]**Керування запуском:** Створено файл `testng.xml`, у якому чітко визначено склад тестового набору та вказано, які саме групи тестів мають бути виконані.

### Порівняння з JUnit Jupiter
На основі виконаної роботи було зроблено висновок, що TestNG пропонує більш гнучкі інструменти для організації складних сценаріїв тестування . Зокрема, механізм групування та параметризація через `@DataProvider` є більш явними та зручними для великих проєктів.

### Аналіз покриття коду
За допомогою плагіна **JaCoCo** було згенеровано звіт про покриття коду (Code Coverage)[cite: 1180, 1303]. [cite_start]Аналіз звіту підтверджує, що тестові сценарії охоплюють основні гілки логіки та граничні умови моделі.
