# Лабораторна робота №3
## Модульне тестування в JUnit Jupiter

### Мета роботи
Сформувати практичні навички модульного тестування Java-коду засобами JUnit Jupiter, організації Maven-проєкту та аналізу покриття коду за допомогою JaCoCo.

### Опис предметної галузі
Для тестування використано модель автобусного парку, розроблену в попередніх роботах. Основна логіка включає управління сутностями водіїв (`Driver`), транспортних засобів (`Bus`) та розкладу рейсів (`Route`).

### Реалізація тестування
У ході роботи було створено набір модульних тестів для перевірки ключової логіки системи:

* **Фікстури тесту:** Використано анотацію `@BeforeEach` для створення стабільного початкового стану об'єктів перед кожним тестовим методом.
* **Позитивні сценарії:** Перевірка коректного створення об'єктів та успішного виконання предметних операцій (наприклад, призначення рейсу водію)[cite: 223, 262].
* **Негативні сценарії:** Перевірка реакції системи на некоректні дані (наприклад, спроба створити автобус із від'ємною місткістю) за допомогою `assertThrows`].
* **Граничні сценарії:** Перевірка роботи системи з мінімально допустимими значеннями аргументів.

### Структура проєкту
Проєкт організовано як стандартний Maven-проєкт із чітким розділенням коду:
* `src/main/java` — основна логіка моделі.
* `src/test/java` — класи модульних тестів.
* `pom.xml` — конфігурація залежностей (JUnit Jupiter) та плагінів (JaCoCo).

### Аналіз покриття коду
Для аналізу повноти тестування було налаштовано плагін **JaCoCo**. Звіт про покриття дозволяє переконатися, що всі ключові методи та розгалуження бізнес-логіки були виконані під час запусків тестів.

### Висновок
Впровадження модульного тестування дозволило систематизувати перевірку поведінки програми. Використання Maven забезпечило автоматизацію процесу збірки та тестування, що робить розробку більш надійною та професійною.
